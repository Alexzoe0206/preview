02 · Transformation path

五段路徑，
從產品設計走到企業 DNA。

每一段都有具體交付物，也都有做過的案例。可以從任何一段開始；點節點看細節。

  1. 先讓第一線用得懂。

    從使用者研究與任務分析開始，把設備、App 與介面的操作重新設計。

    • 使用者研究
    • 任務流程
    • UI／UX 與 HMI
    • 金融ATM 使用者研究 →
    • 政府與研究機構主軸監控 HMI →

  2. 再把卡關的步驟拿掉。

    把現場、表單與部門之間的交接畫成流程圖，找出等待、重工與斷點。

    • 現況流程圖
    • 服務藍圖
    • 待改造清單
    • 物流交通驗收流程改造 →
    • 半導體與製造自助 Kiosk →

  3. 讓流程長在系統裡。

    前後端、API 與管理後台一起設計，讓新流程不靠人記、不靠紙本。

    • 資訊架構
    • 前後端與 API
    • 管理後台
    • 半導體與製造企業 E 化系統 →
    • 半導體與製造廠商進場後台 →

  4. 讓管理者一眼看見現場。

    定義指標口徑，把生產、設備與服務資料做成看板、趨勢圖與報表。

    • 指標定義
    • 儀表板與看板
    • 報表
    • 半導體與製造Digital Kanban →
    • 醫療與生醫雲端復健數據 →

  5. 最後，改變的是組織怎麼做決定。

    把流程、系統與數據沉澱成團隊的工作方式；現在再加上 AI 團隊，讓人專心做決策。

    • 營運節奏
    • AI 團隊與權限
    • 知識底座
    • 政府與研究機構FDA AI 顧問系統 →

05 · Approach

同樣叫轉型，
起點不一樣，結果就不一樣。

我們不先賣系統。先把現場流程畫出來，再決定哪裡做成系統、哪裡做成看板、哪裡交給 AI。

比較項目常見的轉型做法AZUL 轉型路徑
起點—先選一套系統先把現場流程畫出來
參與的人—IT 部門與廠商第一線、管理者與 IT 一起
交付—系統上線流程、系統、看板一起上線
數據—上線後才想報表先定義指標口徑，再畫圖表
結束點—驗收就結束沉澱成團隊的工作方式，再接 AI
